# Contributing to Minion Yuri

Thanks for wanting to help! Minion Yuri turns NASA SPHEREx images into blinking
animations so moving and changing objects stand out. This page says how to get
set up and how we work. By taking part you agree to our
[Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to help

- **Report a bug** or **suggest a feature**: open an
  [issue](../../issues/new/choose) using one of the templates.
- **Fix something**: look for open issues, comment that you're taking one, then
  open a pull request.
- **Add a built-in target**: see [Add a target](#add-a-built-in-target) below.
- **Improve the docs**: the [README](README.md), [backend/readme.md](backend/readme.md)
  and [frontend/readme.md](frontend/readme.md).

Found a security problem? Don't open an issue; follow the
[Security Policy](SECURITY.md).

## Get set up

You need **Python 3.11+** and **Node.js 18+**. Full steps are in the README's
[Getting Started](README.md#getting-started); the short version:

```bash
# terminal 1: backend
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn api:app --reload --port 8000
```

```bash
# terminal 2: frontend
cd frontend/minion-yuri
npm install
npm start
```

No internet, or don't want to wait for NASA's archive? Set
`REACT_APP_USE_MOCK=true` in `frontend/minion-yuri/.env.local` to use
`public/mock/frames.json` instead of the backend.

## How we work

1. **Branch per feature.** Branch off `main`, e.g. `feature/gif-export` or
   `fix/loupe-offset`, and work there.
2. **Keep `main` working.** Pull `main` into your branch before asking for a
   review, and only merge when your change works against the API contract
   (see [API](README.md#api)).
3. **Open a pull request.** The template asks for:
   - *What works now*
   - *Ready for others*: what teammates can now use
   - *Note*: gaps and known issues
4. **Get one review** from someone who owns that area (see
   [Features and Owners](README.md#features-and-owners)).
5. **Blocked for 30+ minutes?** Say so in the group chat or on the issue.

## Code rules

- **Frontend:** components never fetch. Every backend call goes through
  [`src/api/frames.js`](frontend/minion-yuri/src/api/frames.js).
- **Backend:** the frontend never sees FITS files, only JSON and PNGs.
  Each pipeline step lives in its own file under `backend/pipeline/`.
- **Units:** RA/Dec in decimal degrees, FOV in arcminutes, arrays 1–6
  (short → long wavelength), dates as `YYYY-MM-DD`.
- **API changes:** if you change what an endpoint returns, update
  [backend/readme.md](backend/readme.md), the mock in `public/mock/frames.json`
  and the README's API table in the same pull request.
- **Don't commit data or secrets.** `backend/output/`, `.venv/` and
  `deploy/.env` are git-ignored; keep them that way. The exception is
  `frontend/minion-yuri/public/baked/`, which is generated by `bake.py` and
  deployed with the site.

## Add a built-in target

1. Get today's position and proper motion: `GET /api/resolve?name=<target>`.
2. Add an entry to
   [`src/data/target.js`](frontend/minion-yuri/src/data/target.js): name,
   `ra`/`dec` (use `ra_now`/`dec_now`), proper motion, best `array`, and
   optional `aliases`.
3. Bake it: `cd backend && .venv/bin/python bake.py "<target>"`.
4. Add it to the [Built-in Targets](README.md#built-in-targets) table.
5. Commit `public/baked/` with your change and open a pull request.
